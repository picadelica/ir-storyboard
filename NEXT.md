## Важное про upstream-контекст

Основной разработчик передал Claude artifact «Онбординг IR Storyboard».
Это runbook оригинального проекта: `dechernov-stack/ir-storyboard`, ветка
`feat/v2`, production-сервер, оркестратор, доступы и правила второго
разработчика.

Для текущего workspace это **карта подключения к основному проекту**. Наша задача
не держать отдельный форк навсегда, а подготовить новый дизайн и UX-путь входа
данных как совместимый вариант интерфейса поверх основного проекта, его БД,
ключей и production-контура.

При этом это не разрешение самостоятельно деплоить production, менять доступы
или переподключать remote без явного решения пользователя.

Работаем так:

- UI/UX-изменения пока сохраняем в `origin/main` форка Picadelica.
- Дизайн должен оставаться совместимым с API и данными основного проекта.
- Данные, seed-файлы, SQLite-схему, backend-контракты и смысл API не менять без
  отдельного явного решения пользователя.
- Если пользователь говорит «пуш» — пушить в `origin/main`, пока он явно не
  говорит про другой remote/branch.
- Доступ к основному репозиторию есть, он добавлен как `upstream`.
- Перед реальным переносом сравнить ветки и выделить изменения:
  - безопасные frontend/design/UX;
  - изменения API/types;
  - backend/data/schema-риски.
- При будущей интеграции внимательно проверять зоны конфликтов:
  `frontend/src/components`, `frontend/src/App.tsx`, `frontend/src/api.ts`,
  `frontend/src/types.ts`, `CLAUDE.md`, `NEXT.md`.
