## Что сделано за сессию: верификация фактологии — Фаза 1

Проблема: research/deep-research факты галлюцинируют и склеивают сущности (на gonka
биографию Хачуяна слепило с Либерманами в одного «фаундера»). YouTube/аудио безопасны
(цитаты+таймкоды). Построен контур доверия.

- **Схема** (`db.init_schema`): facts += `verification` (verdict), `verification_note/_sources/_at`,
  `entity`, `state` (active|rejected). Новые `entities` + `entity_facts` — якорь идентичности
  (компания/фаундеры/двойники) вне нарративной матрицы, source-linked.
- **Движок** `ir_storyboard/verification.py`: `audit_client` (скептический аудит сущностей,
  per-fact вердикт + предложенный canonical), `verify_claims` (Tavily + grounded-вердикт).
  Транскриптные факты не проверяются. Stub-safe.
- **API** (`backend/main.py`): `POST /clients/{id}/audit` (гоняет аудит, проставляет вердикты,
  бутстрапит черновик якоря), `verify-claims`, `/facts/{id}/verification|reject|restore`,
  CRUD `/entities`. Rejected исключён из агрегатов/циклов/scorecard/punch; в дровере ячейки
  показан зачёркнутым + «вернуть».
- **UI**: вкладка Health → «Проверка фактов» (`FactAuditView`): якорь идентичности (карточки,
  подтверждение, ссылки) + триаж (снять/оставить, массово по сущности, прыжок в ячейку).
  Бейджи доверия + чип сущности + снять/вернуть в `CellDrawer`.
- **Тесты**: `test_verification.py` (5) + `test_verification_api.py` (4), офлайн.
- **Валидировано на боевой gonka** через задеплоенный модуль: available=True, 23 факта
  флагнуто из 157 archival, canonical company=`Gonka.ai`. Прототипом ранее подтверждено,
  что веб-проверка чисто разводит Хачуян↔Либерман.

**Фаза 2 — ворота на ингесте:**
- `verification.verify_candidates(candidates, anchor)` — скептический фильтр ПЕРЕД коммитом:
  флагает кандидатов, относящихся к двойнику / противоречащих якорю / похожих на выдумку.
  Нет якоря или stub → пропускает всё (degrade-open; первый батч ловит переаудит).
- `commit_llm_report` верифицирует извлечённые факты до записи; suspect/refuted коммитятся,
  но в карантин `state='review'` (вне матрицы), пока человек не промоутит. Возвращает `held_facts`.
- API: `GET /clients/{id}/review-queue`, `POST /facts/{id}/promote`. UI: секция «На ревью с
  ингеста» в «Проверке фактов» (в матрицу / снять); в результате ингеста «N придержано воротами».

**Фаза 3 — дедуп/слияние:**
- Новая таблица `fact_sources` (мультиисточник для слитого факта).
- `verification.find_duplicate_groups()` — LLM-кластеризация околодублей по подсекции →
  предложения слияния. `matrix.merge_facts(keep, ids)` — сворачивает источники дублей в
  корроборацию keep'а, дубли мягко-rejected. `n_sources` = 1 + слитые источники (сигнал доверия).
- API: `POST /clients/{id}/find-duplicates`, `POST /facts/merge`. UI: секция «Дубли»
  (найти → группы → слить в один) в «Проверке фактов»; бейдж «N независимых источника» в ячейке.

**Грунтованный гайд интервью (заменил статические шаблоны):**
- `ir_storyboard/interview.py` `build_guide()` — одна проходка по ПРОВЕРЕННЫМ фактам
  (state=active, не suspect/refuted) + якорь → структурный JSON {dossier, diagnosis
  {covered,gaps,priorities}, arcs[questions{question,targets,know,close,followups}]}.
- API `POST /clients/{id}/interview-guide`. UI: `InterviewView` переписан (Сгенерировать
  гайд → досье + диагноз + дуги; вопросы грунтованы, targets прыгают в ячейки, follow-ups).
- Валидировано на gonka: 8 дуг, грунтованные вопросы. Замкнутая петля: почистил матрицу
  через «Проверку фактов» → гайд авто-улучшается.

**Дисциплина грунтования гайда:** факты в промпт идут с `id`; модель обязана указать `grounds`
(id фактов-опор) на каждый вопрос и НЕ называть числа/имена/даты, которых нет в процитированных
фактах (вместо этого — спросить у фаундера). `grounds` резолвятся в тексты, неизвестные id
отбрасываются. UI: под вопросом «основано на N факт(ах)» (раскрывашка); без опоры — «открытый
вопрос». Валидация на gonka: 15/15 вопросов с grounds, выдуманное «N приложений» ушло.
