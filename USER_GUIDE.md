# IR Storyboard — руководство пользователя

> Для аналитиков и менеджеров IR-агентства, работающих с системой.
> Технические детали (стек, деплой, архитектура) — в `README.md` и `CLAUDE.md`.

---

## Зачем эта система

Под каждого клиента (фаундера/компанию) ведётся **нарративная матрица**: 24
ячейки = 8 концентрических слоёв × 3 подсекции. От самой личной (L1 — личная
история фаундера) до самой внешней (L8 — макроконтекст/PEST).

В ячейки заносятся **факты** — атомарные утверждения с источником, флагом
(🟢 «работает в нашу пользу» / 🔴 «риск, надо разрулить» / ⚪ «явный пробел»)
и каналом происхождения (откуда узнали).

На основе фактов система:

- показывает **дыры в покрытии** (Punch-list, Scorecard, Interview Qs);
- держит **очередь работы** для аналитика (Work);
- по нажатию кнопки собирает **артефакты** (Weekly бриф, Event-реакция,
  Квартальный досье) для скриптрайтеров и NotebookLM.

Главное правило: матрица — **персистентная**. Факт записывается один раз,
никогда не редактируется (новая версия = новый факт), и всегда с провенансом
(URL или название интервью + цитата). Это исключает «правда меняется
задним числом».

## Глоссарий

| Термин | Что значит |
|---|---|
| **Layer (слой) L1–L8** | Концентрический круг: L1 = личная история фаундера, L2 = профессиональная история, …, L8 = PEST/макро. У каждого слоя 3 подсекции, итого 24 ячейки. |
| **Subsection (ячейка)** | Конкретный пункт внутри слоя, например `1.1 Origin & Childhood`. Идентификатор всегда `<layer>.<n>`. |
| **Fact (факт)** | Атомарное утверждение в ячейке. У каждого факта обязательно: текст, флаг, канал, провенанс. |
| **Flag (флаг)** | 🟢 green — играет на нарратив. 🔴 red — потенциальный риск, надо учесть. ⚪ grey — явный gap, нет данных. |
| **Channel (канал)** | Откуда добыт факт: `offline_interview` (живое интервью аналитиком), `online_interview` (подкаст/YouTube), `archival` (документы), `online_research` (поиск в сети). Каналы методологически ограничены по слоям (см. ниже). |
| **Track (narrative track)** | Сюжетный фокус на квартал: «о чём именно мы рассказываем». У трека есть имя, angle, target layers/subsections и приоритет. Без активного трека Weekly / Event / Quarterly cycle **не работают**. |
| **Cycle** | Один из 3 шаблонов производства: weekly (короткий бриф под видео), event (реакция на инфоповод), quarterly (полный досье). |
| **Provenance** | Источник факта: URL для онлайн-каналов или название интервью для offline, плюс «evidence snippet» — цитата ≥ 20 символов. Без provenance система факт не примет (422). |

## Quickstart — типовые сценарии

Это раздел «делай раз, делай два». Смотри сюда первым.

### 1. Новый клиент в системе

```
Sidebar (слева)
└─ Clients
   └─ [+ New]   ← на самом верху списка
```

Откроется выезжающая панель. Два варианта:

- **Manual** — заполни поля: `id` (slug, латиница, например `acme-inc`),
  `name`, `sector`, `one-liner`, имя/handle фаундера. Опциональные. Sector
  можно писать как `fintech` или `b2b-saas/lending`.
- **Import YAML** — вставь YAML целиком (формат показан в placeholder), удобно
  когда клиента готовят оптом.

После сохранения клиент появляется в сайдбаре, ты сразу попадаешь на
вкладку **Matrix** (пустая матрица из 24 ячеек).

**Пилотные данные (если хочешь посмотреть как всё устроено на готовом):**
в пустой системе на боковой панели есть кнопка
«+ Загрузить пилот (Accumulator)» — подтянет демо-клиента с фактами на
24 ячейки и planом на квартал.

---

### 2. Завести план на квартал (narrative track)

**Это обязательно, иначе Weekly / Event / Quarterly не запустятся.**
Без трека система не знает, на каких слоях фокусироваться.

```
[Tabs] Matrix · Plan · Ingest · YouTube · Research · Work · ...
                 ↑
                 эта вкладка
```

1. Открой **Plan**. Сверху написан текущий квартал — он берётся из
   `Quarter` в сайдбаре (по умолчанию `2026Q2`).
2. Нажми **[+ New track]**.
3. Заполни:
   - **Name** — короткое имя, например `Founder origin story` или
     `Why now: regulatory tailwind`.
   - **Angle** (опционально, но рекомендую) — одно предложение про
     cause → effect → so what. Это попадает в prompt при генерации
     артефактов и сильно влияет на тон.
   - **Target layers** — чекбоксы L1–L8: на каких слоях фокусироваться.
     Если нужна гранулярность точнее (отдельные подсекции, не целые
     слои) — переключи `→ pick individual subsections`.
   - **Priority** — `1` = самый важный. Weekly cycle берёт **трек с
     highest priority** (наименьшим числом).
4. **[Create track]** → трек появится в списке.

Можно завести несколько треков на квартал (например 3) — Weekly возьмёт
priority 1, Quarterly умеет ходить по всем.

**Если ошибся** — пока нет edit/delete в UI. Создавай новый с
правильными значениями и поставь старому большой priority (например 99),
чтобы он не выбирался.

---

### 3. Залить экспертный LLM-отчёт (Ingest)

Сценарий: эксперт принёс отчёт из ChatGPT Deep Research / Claude /
Perplexity / Gemini в виде `.docx` / `.md` / `.txt` / `.pdf` со списком
фактов и пронумерованными ссылками `[1]`, `[2]` снизу.

```
Tabs → Ingest
```

1. Выбери **LLM Agent** (от какого ИИ отчёт) — это меняет промпт-эвристики
   разбора.
2. Перетащи файл в drop-zone (или клик → выбери файл).
3. Подожди — система проанализирует документ и покажет **Preview** со всеми
   извлечёнными фактами. У каждого факта:
   - текст,
   - предлагаемая ячейка матрицы (можно сменить),
   - флаг (можно сменить),
   - источник (URL + цитата из текста),
   - чекбокс «оставить / отбросить».
4. Можно правки делать массово: **чекбоксы + sticky-toolbar сверху** —
   drop / restore / set flag / move to subsection.
5. Когда довольна выборкой → **[Commit]** внизу. Факты пишутся в матрицу,
   ты попадаешь на Done-экран со ссылкой на ячейки.

**Идемпотентность.** Повторный ingest того же отчёта = 0 new sources / 0
new facts. Не бойся залить дважды.

**Идеальный input** — отчёт по нашему промпт-шаблону. Шаблоны для
эксперта в `LLM_REPORT_PROMPT_TEMPLATES.md` (отдать аналитику, который
заказывает Deep Research).

---

### 4. Залить интервью с YouTube

Сценарий: фаундер выступил у Боброва / Лебедева / в подкасте — есть URL.
Хотим вытащить факты L1–L3 (личное) и L4–L7 (компания/индустрия).

```
Tabs → YouTube
```

1. Вставь URL (`https://youtube.com/watch?v=…` или `youtu.be/…` —
   нормализуется автоматически).
2. Опционально: указать email для уведомления.
3. **[Preview]** → запускается пайплайн:
   - скачивание аудио (yt-dlp);
   - разбивка на 10-минутные чанки (с overlap);
   - транскрипция (faster-whisper / OpenAI / Deepgram, что настроено);
   - LLM-экстракт фактов чанк-за-чанком.
4. На preview-экране:
   - **сверху** — brief (3-6 предложений: кто кого интервьюирует, темы)
     + per-cell coverage (какие ячейки тронуты);
   - **по фактам** — то же что в LLM Report: чекбокс / флаг / ячейка /
     timestamp URL (YouTube ссылка с `&t=` на момент в видео) +
     literal snippet из транскрипта.
5. **[Commit]** → факты записаны.

**Layer guard.** Веб-факты в L5/L6/L8 для YouTube канала автоматически
помечаются как `skipped` — `online_interview` каналу методология этого не
разрешает. Если факт реально важен — можешь явным кликом override на
preview-экране.

**Reopen.** На upload-экране есть **History** — таблица прошлых ingest'ов
с кнопкой Reopen (read-only review старого preview).

**Sonnet fallback.** Если Haiku упал на чанке (overload / cutoff JSON) —
ретрай 1 раз на Sonnet. В preview увидишь `chunk_errors[].reason =
"fallback_used"`.

---

### 5. Залить статью или транскрипт через Research

Сценарий: нашёл статью / расшифровку → хочешь быстро выдернуть из неё
факты.

```
Tabs → Research
```

Два режима:

**5a. Tavily-поиск.** Жмёшь **🔍 Search online** — система собирает
запросы из имени фаундера + sector + тикера, ходит в Tavily, возвращает
hits. По каждому hit'у есть кнопка **[Extract facts →]** — LLM
извлекает из сниппета / полного текста факты.

**5b. Ручная вставка.** На каждом hit'е есть **[Paste full text]** —
открывается textarea, можешь вставить полный текст статьи / транскрипта.
Тогда экстрактор работает не по сниппету, а по полному тексту (фактов
будет больше).

Дальше: классический preview → чекбоксы → **[Импортировать N фактов]**.

**YouTube-ссылка в результатах поиска.** Если в hit'е URL ведёт на
YouTube — увидишь **pink-баннер** «🎥 Это YouTube-ссылка — лучше через
YouTube Ingest» + кнопка **[Process via YouTube ingest →]**. Она кинет
тебя на вкладку YouTube с уже подставленным URL — там пайплайн
богаче (timestamp, brief, layer guard).

---

### 6. Прогнать Weekly бриф

Сценарий: пятница, надо сдать видео-бриф на неделю.

**Предусловие:** на квартале должен быть активный narrative track (см. сценарий 2).

```
Sidebar → внизу → [Weekly бриф]
```

1. Откроется модалка `Cycle: weekly`.
2. **Week label** — по умолчанию `2026-W21` (вычисляется автоматом).
   Менять обычно не надо.
3. **Max facts in brief** — по умолчанию 3. Сколько фактов цикл втащит в
   бриф. Для длинного видео можно поставить 5-6.
4. **[Run]** → LLM генерит markdown-артефакт (Hook / Narrative thread /
   Talking points / Close), сохраняет в БД, ты попадаешь на вкладку
   **Artifacts** с открытым новым артефактом.
5. Если факты «жидкие» — бриф предупредит:
   `> ⚠ No fresh green/red facts in target cells this week.` — это
   значит, что в target subsections трека нет свежих green/red.
   Решение: либо залей новых фактов, либо переключи трек.

**Если получишь ошибку «No narrative tracks…»** — система не нашла трек
на квартал. Появится amber-карточка с кнопкой **[Открыть Plan →]** —
заведи трек и повтори.

**Event-реакция** работает аналогично: вводишь короткий текст события
(«SEC выпустил новые правила», 2-4 предложения), выбираешь куда оно
«приземлилось» (subsection) → артефакт-реакция.

**Квартальный досье** — большой обходной артефакт по всем target слоям
трека. Параметры: traversal (`inside_out` или `outside_in`) и
`facts_per_subsection` (сколько фактов на ячейку).

---

### 7. Завести / закрыть work item

Work item = открытая задача для аналитика, привязанная к ячейке. Бывают
4 типа: `fill_gap` (заполнить grey), `interview` (спросить на ближайшем
интервью), `adjacent` (соседняя тема, надо копнуть), `cross_ref`
(сверить с другой ячейкой).

```
Tabs → Work
```

Канбан с 4 колонками: `Open`, `In progress`, `Blocked`, `Done (14d)`.

- **Создать** — есть два пути:
  - **[Synthesize]** (кнопка справа сверху) — система генерит работы из
    текущего punch-list-а и тонких ячеек.
  - Из drawer-а ячейки (открой ячейку из Matrix, там можно завести
    work item вручную).
- **Открыть item** → drawer с: title, статус, priority, ссылка на
  ячейку (clickable), notes.
- **Закрыть** — меняешь статус на `done`. История остаётся.

**Идемпотентность.** Повторный Synthesize не создаст дубль если open
work item на ту же ячейку с тем же типом уже есть.

---

### 8. Понять где у клиента дыры

Три вью, три ракурса:

| Вкладка | Что показывает | Когда смотреть |
|---|---|---|
| **Punch-list** | Список grey-ячеек (явных пробелов) сгруппирован по слоям. Кликабельно — прыгает в Matrix к нужной ячейке. | Когда планируешь work на неделю — это сырьё для Work. |
| **Interview Qs** | Сгенерированные вопросы для следующего интервью с фаундером (по grey-ячейкам L1–L3, чуть L4). | Перед интервью — экспортируешь как чек-лист. |
| **Scorecard** | Сводка по слоям: сколько green / red / grey, % покрытия. | На квартальном ревью клиента — где мы готовы / где не готовы. |

## Цветовые флаги, каналы, слои — контекст

### Флаги

- **🟢 green** — играет на нарратив (хорошо для пиар-питча).
- **🔴 red** — потенциальный риск или возражение (надо знать, чтобы
  опередить).
- **⚪ grey** — явный пробел. Это не «факт-заглушка», это **запись о
  том, что мы не знаем X**. Grey специально вводится через UI или
  LLM-извлекатель, когда тема названа, но содержимого нет.

Provenance:

- 🟢🔴 факт из онлайн-канала **обязан** иметь `http(s)://` URL и
  `evidence_snippet` ≥ 20 символов. Иначе 422.
- 🟢🔴 факт из offline-интервью **обязан** иметь `source_title` (типа
  `"Interview with X 2026-05-12"`). Snippet опционален.
- ⚪ grey — snippet опционален.

### Каналы и слои

Каждый слой методологически разрешён только из определённых каналов.
Главное:

- **L1–L3** (личная и проф история фаундера) — только из
  `offline_interview` и `online_interview` (подкасты/YouTube с самим
  фаундером). Веб-факт в L1/L2/L3 будет автоматически отброшен с
  warning'ом — не баг, by design.
- **L4–L7** — открыты для всех каналов.
- **L8 (макро/PEST)** — обычно `online_research` + `archival`.

### LayerGuard для YouTube

YouTube-ingest применяет `LayerGuard`: факты в **L5/L6/L8** маркируются
`skipped` потому что у `online_interview` нет методологического права
делать утверждения про индустрию/конкурентов/PEST. Аналитик может
override руками на confirm-экране.

## Справочник по вкладкам

### Sidebar (левый бок)

Постоянно виден.

- **Clients** — список клиентов. Кликнул → переключился. `+ New` —
  завести.
- **Quarter** — текущий квартал. Меняешь — список треков, weekly week
  label и т.п. подстраиваются.
- **Active narrative tracks** — read-only список треков на квартал.
  Заводятся во вкладке Plan.
- **Run cycle** — 3 кнопки: Weekly бриф / Event-реакция / Квартальный
  досье. Открывают `CycleRunner` модалку.

---

### Matrix

Главный экран. 24 ячейки сеткой. В каждой ячейке:

- индикатор покрытия (сколько фактов, какие флаги преобладают);
- иногда «топ-факт» в превью.

Клик по ячейке → справа выезжает **CellDrawer** со всеми фактами в
ячейке. В drawer-е можно:

- посмотреть факт целиком, его источник, snippet, captured_at;
- добавить факт вручную (`+ Add fact`) — выбрать флаг, канал, ввести
  текст + provenance;
- удалить факт (он не пропадает физически, но скрывается из вью);
- завести work item на эту ячейку.

### Plan

Описано в сценарии 2. Сейчас: list + create. Edit/delete будут позже
(нужны мутационные endpoints на бэке).

---

### Ingest (LLM Report)

Описано в сценарии 3. Под капотом:
файл → парсер → разбор `[N]` цитат → LLM-классификация по ячейкам →

### YouTube

Описано в сценарии 4. Под капотом:
URL → yt-dlp → opus 16kHz mono → split на чанки ≤3600s + overlap →

Внутри есть `Reopen` старого preview (read-only).

---

### Research

Описано в сценарии 5. Кнопка Tavily-поиска + per-hit extract + paste full
text + YouTube redirect.

---

### Work

Описано в сценарии 7. Канбан 4 колонки.

---

### Punch-list

Read-only. grey-ячейки сгруппированы по слоям, с прыжком в Matrix.

---

### Interview Qs

Read-only. Сгенерированные вопросы под следующее интервью с фаундером.

---

### Scorecard

Сводная таблица по слоям: green / red / grey counts, % покрытия. На
квартальный ревью с клиентом.

---

### Artifacts

История всех созданных артефактов (weekly / event / quarterly).
Кликнул → видишь markdown целиком + meta (track, fact ids, week label).
Удобно копировать в NotebookLM.

---

### Methodology

Тонкая настройка как LLM понимает ячейки. **Не лезть без причины** —
дефолтные описания заполнены русским языком на все 24 ячейки.

Два режима:

- **Global descriptions** — описание ячейки общее для ВСЕХ клиентов
  («что в принципе сюда относится / что НЕ относится»). Инжектится в
  prompt как `"Methodology note: …"` под каждой ячейкой в списке для
  LLM.
- **For \<client name\>** — приписка только для этого клиента
  (additive поверх global). Инжектится как `"For this client: …"`
  отдельной строкой.

Плюс **Tone preset** per-client (4 пресета: academic / business /
narrative / punchy). Меняет регистр генерируемых артефактов.

## Типичные ошибки и что они значат

| Сообщение | Что произошло | Что делать |
|---|---|---|
| `422 ... No narrative tracks for <client> in <quarter>. Define a plan first.` | Cycle не нашёл активного трека. | Открой Plan-вкладку и заведи трек (см. сценарий 2). На weekly теперь автоматически появляется amber-карточка с кнопкой «Открыть Plan →». |
| `422 ... evidence_snippet must be at least 20 characters` | Пытаешься залить онлайн-факт без цитаты или со слишком короткой. | Расширь snippet до полноценной фразы (≥ 20 символов). |
| `422 ... source URL required for online channel` | Онлайн-факт без URL. | Добавь источник, либо переключи флаг на grey (там URL необязателен). |
| `422 ... layer L1 not allowed for channel online_research` | Веб-факт в L1–L3 — by design отбит. | Перенеси в L4+ или замени канал на интервью (если факт из подкаста/беседы). |
| `chunk_errors[].reason = "fallback_used"` (в YouTube preview) | Haiku не справился с чанком, отработал Sonnet-фоллбек. | Информационное, не ошибка. Просто знай, что 1 чанк дороже стоил. |
| `skipped` в YouTube preview с пометкой LayerGuard | Факт на L5/L6/L8 от `online_interview` отбит автоматом. | Если факт реально важен — override руками кликом на preview-экране. Иначе ничего делать не надо. |
| `> ⚠ No fresh green/red facts in target cells this week.` в weekly | Цикл сработал, но в target subsections нет новых фактов. | Либо залей фактов через Ingest / YouTube / Research, либо переключи трек / расширь target layers. |

## FAQ для команды

**Можно ли редактировать факт?**
Нет. Факты иммутабельные by design. Если факт устарел — заведи новый с
актуальной формулировкой; старый останется в истории (с `captured_at`).

**Можно ли удалить факт?**
Технически да (через CellDrawer), но факт «спрячется», не исчезнет
физически — work-item-ы, которые он закрыл, останутся со ссылкой.

**Почему мой LLM-отчёт залился, а в матрице 0 фактов?**
Скорее всего эксперт прислал отчёт без `[N]` нумерованных ссылок снизу —
парсер не смог сопоставить факт ↔ URL. Решение: пересдать отчёт по
шаблону из `LLM_REPORT_PROMPT_TEMPLATES.md`.

**Почему YouTube ingest идёт 5-10 минут?**
Нормально. 1-часовое интервью = ~6 чанков × (транскрипция + LLM-extract).
Можно повесить email-уведомление в форме.

**Можно ли вести двух клиентов параллельно?**
Да, переключение через сайдбар. Состояние preview / форм per-client (для
YouTube — через `localStorage[yt-ingest-${clientId}]`).

**Как удалить клиента?**
Через CLI на сервере (см. `CLAUDE.md`, секция CLI). В UI пока нельзя —
осознанно, чтобы случайно не потереть.

**Где история изменений?**
Каждый факт имеет `captured_at`. Прямого diff-вью нет (см. README, секция
«осознанно не сделано»), но можно сортировать факты в ячейке по дате.

**Bug / feature request?**
Через менеджера агентства в bugtracker. К сообщению прикрепить:
client_id, что нажали, что ожидали, что получили, скриншот ошибки.

## Что осознанно не сделано

- **Авторизации/пользователей нет** — система внутренняя, доступ
  ограничен IP агентства.
- **Real-time collab editing нет** — если двое одновременно правят одну
  ячейку, last-write-wins.
- **Мобильного layout-а нет** — десктоп only.
- **Diff-вью истории нет** — только сортировка по `captured_at`.
- **Удаления клиента через UI нет** — только через CLI на сервере.
- **Edit/delete треков через UI нет** — только создание (backend пока
  без мутационных endpoints).

Эти ограничения известны и не считаются багами.
